# 高校就业推荐平台：学生端 / 企业端多维度 UX 审计报告

> 对应毕业论文「系统测试」章节素材。评分源自人工走查记录（`STUDENT.md` / `COMPANY.md`），技能链路 API 对照见 `API.md`。  
> 审计时间：2026-11-03（Asia/Shanghai）。未改业务代码。

## 1. 测试目的与范围

### 1.1 目的

对毕业设计「高校就业推荐平台」的**学生端**与**企业端**进行多维度用户体验（UX）审计，重点验证：

1. 技能标签体系在档案、职位、推荐、候选人链路中是否一致可用；
2. 核心求职 / 招聘流程是否可完成、反馈是否清晰；
3. 推荐与 AI 助手是否符合角色人设与期望方向；
4. 演示数据与界面呈现是否影响毕设答辩演示可信度。

本报告**不替代**功能回归与接口自动化测试；技能相关接口另做专项对照（见第 6 节，PASS=19）。

### 1.2 范围

| 角色 | 覆盖场景 | 未覆盖 |
| --- | --- | --- |
| 学生 | 登录首页、个人档案与技能、简历解析、职位列表/详情、为你推荐、投递与列表、收藏、就业助手、求职看板 | 面经社区发帖、管理员端 |
| 企业 | 登录落地与招聘看板、企业资料与资质、职位发布与技能标签、候选人列表/详情、投递状态流转、面试安排、招聘助手 | 未过审侧栏禁用态、真实发笔试/面试通知落库后的学生端回显 |
| API | 登录、技能标签、学生技能 CRUD/合并、推荐、企业职位技能、候选人详情技能、跨企业 IDOR | 助手流式 SSE、薪资预测单独压测 |

### 3.2 学生端关键问题（摘要）

- **测试数据污染首页与列表**：顶栏黄色「即将到来的笔试/面试」与首页「未来 7 天」重复；最新职位出现「越权隔离职位*」；投递列表大量「已录用」测试记录。
- **双简历体系**：PDF 技能解析在「个人档案」，投递用的是「在线简历」；默认简历为测试简历，易投错。
- **推荐与期望方向不符**：期望杭州后端，Top1 为网易游戏体验设计实习（匹配 80.9），嵌入式岗无技能重合仍进前三；理由模板反复「Java/MySQL/Spring Boot 67%」。
- **职位详情可读性**：任职要求直接渲染爬虫 JSON；职责正文含抓取元数据；技能 tag 不区分「我会/我不会」。
- **就业助手引用错位**：搜 Java 校招时正文 5 条与参考来源（含 HRSSC、PMO）不一致。
- **看板误导**：投递环图被测试「已录用」撑满；技能雷达轴混入 STM32/RTOS，缺少本人 Vue/Redis/Docker/Spark。

## 5. 跨角色对照

| 对照项 | 学生端 | 企业端 | 结论 |
| --- | --- | --- | --- |
| **技能词表** | `GET /public/skill-tags`，下拉 `名称 (方向)`（半角括号）；可「自定义新技能」 | 同一接口，下拉 `名称（方向）`（全角括号）；多选不可创建 | **同一本 `skill_tag`**，括号写法不一致；学生自定义不会自动进入企业可选 tag，词表可分叉 |
| **熟练度呈现** | 1–5 星 + 入门/掌握/熟悉/熟练/精通 | 候选人抽屉「Java · 4」裸数字，无图例 | **同一字段两套 UI**，企业侧难读 |
| **匹配分** | 推荐卡、首页推荐有匹配分（质量另议） | 候选人列表无匹配分、无技能列 | 技能在企业侧停在「打标签」，未完成「用来筛」 |
| **状态机** | 投递列表：待初筛 / 面试中 / 已录用等；看板环图同名 | 候选人改状态：待初筛→笔试/面试中/未通过→已录用；看板漏斗同名 | **状态名一致**；演示库「已录用」过多导致两端图表都失真 |
| **助手人设** | 就业助手：三方协议、岗位、薪资、缺技能；工具 `search_jobs` | 招聘助手：写 JD、筛候选人、列职位；工具 `generate_job_description` | **组件相同、示例不同**；企业问运营数据时落到学生兜底文案 → P0 |
| **导航步数（主路径）** | 登录→首页(1)→职位详情(2)→选简历投递(3)→我的投递确认(4) | 登录直接进职位管理(1，非看板)→发职位(2)→候选人(2)→改状态(3) | 学生投递路径清晰；企业登录落地与演示指南「看板入口」不一致 |
| **测试数据** | 越权隔离职位、测试简历、大量已录用 | 同套污染职位/面试 72 条；词表「Rust测试」、分类「测试分类」 | **通库污染**，答辩演示需过滤或换干净账号 |

## 9. 改进建议（按优先级、可落地）

### P0（答辩前必做）

1. **招聘助手角色隔离**：企业会话禁用学生知识库兜底文案；「本周投递概况」应调用看板/投递统计 API 或明确「暂未接入运营数据」，禁止引导「学校就业指导中心」。  
2. **演示数据过滤**：为学生/企业演示账号隐藏标题含「越权隔离」「招聘流程测试」「UX-IDOR」「Rust测试」的职位/简历/面试；或提供「仅展示正式数据」开关。

### P1（主链路）

3. **发职位强制技能**：`tagIds` 至少 1 个；保存校验与红星提示对齐。  
4. **统一简历入口**：投递默认「陈晓-校招简历」或最近编辑；档案解析结果写入可选在线简历；选择器支持搜索。  
5. **职位详情清洗**：任职要求/职责禁止直接渲染 JSON；爬虫字段折叠为「数据来源」；估算薪资加脚注样式。  
6. **推荐可解释**：理由区分技能重合 vs 协同；方向权重抬高，避免 UI/嵌入式岗压过后端期望。  
7. **候选人列表加技能与匹配分列**；熟练度复用学生端星级或统一图例。  
8. **状态变更后刷新抽屉**；待审核职位禁用上架。  
9. **助手引用对齐**：参考来源必须是正文使用的职位/文档；JD 生成从 `skill_tag` 抽样写入任职要求。

### P2（体验打磨）

10. 统一技能括号全角/半角；企业是否允许创建词表走管理端审批。  
11. 调整熟练度文案顺序或改为「1 入门 … 5 精通」单向说明。  
12. 登录 `roleHome` 与演示指南统一为看板；信用代码 18 位+校验位；执照预览失败态。  
13. 面试弹窗展示学生/职位/时间；会议链接可点；空列表 `el-empty`。  
14. 投递/会话列表增加筛选与去重；取消收藏二次确认。
