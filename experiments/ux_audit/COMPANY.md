## 场景 3 职位管理与技能标签

做了什么：打开 `/company/jobs`（共 45 条）。点「发布职位」。打开「技能标签」多选，看到词表。不选任何技能，直接点「保存」，出现「请填写职位名称」「请选择分类」。再填名称「用户体验审计岗位可删」、分类 技术研发 / 后端开发、省份浙江、城市杭州，技能仍为空，保存。职位出现在第一行。未上架、未删除。

看到什么：

- 列表列：职位名称、技术方向、地点、薪资、技能、审核、上架、投递数、操作。技能是浅蓝 tag（Java、MySQL、Spring Boot）。多数「已通过」且上架开关开着；多条「待审核」的测试职位上架开关也是开的。
- 发布弹窗必填红星：职位名称、职位分类、工作地点、月薪、招聘人数、学历、经验、性质。技能标签没有红星，文案是「请选择」。
- 技能是可搜索多选，选项来自统一 `skill_tag`，展示 `名称（方向）`，例如 Java（后端开发）、Spring Boot（后端开发）、Vue（前端开发）、Python（数据开发）、Spark（数据开发）、Flink（数据开发）。下拉约 58 个技能，方向含后端、前端、数据、人工智能、云原生、算法、测试、运维、移动、嵌入式、产品、UI。不能「允许创建」新词。词表里有测试污染「Rust测试（后端开发）」。分类第一级还有「测试分类」。
- 空技能校验：保存时只拦名称和分类，不拦技能。地点是保存前的另一条警告（「请填写省份和城市」），技能没有对应警告。
- 新职位「用户体验审计岗位可删」：后端开发，浙江 · 杭州，8k-15k · 12薪（表单默认薪资），技能列空白，待审核，上架关，投递 0。toast「已保存」。列表不显示职位 id。
- 弹窗很高，保存按钮贴在视口底边。校验时技能下拉还盖住地点，红框和「请选择分类」叠在一起。

| 维度 | 分 | 证据 |
| --- | --- | --- |
| D1 | 2 | 用了统一技能词表和方向，列表也能展示 tag；但技能不是必填，空技能职位可以保存，匹配链路从这里断开 |
| D2 | 4 | 列里有技能、审核、上架、投递，和候选人页对得上 |
| D3 | 3 | 名称/分类校验和「已保存」toast 清楚；技能、职责、要求都可空；待审核职位仍能拨上架 |
| D4 | N/A | |
| D5 | 4 | tag、开关、审核色和全站一致；长表单和盖住字段的下拉是例外 |

问题：

- P1 技能标签可不填就保存。学生端匹配依赖这套 tag，企业侧却能发出无技能职位。
- P1 待审核职位上架开关仍可打开（列表里多条待审核已是开启）。新职位默认是关的，规则不统一。
- P2 词表被「Rust测试」、分类被「测试分类」污染；和学生端括号写法不一致（见文末）。
- P2 界面不给职位 id，审计和删除只能靠标题辨认。

## 场景 7 招聘助手

(a) 想问「帮我写一条 Java 校招 JD 技能要求」。输入框在本环境里无法键入拉丁字母（填进去只剩汉字），所以改点页面自带示例「帮我写一个Java后端校招JD」（`ask()` 会带上 Java）。这是产品自己的示例，不是另一套提示词。

(b) 新对话，发送「本周投递概况」（全中文，原文）。

看到什么：

空态：左栏「会话 / 新对话」，历史标题大量重复（「列出我发布的职位」两条，「帮我写一个Java后端校招JD」两条）。右栏「可以直接提问，或点一个示例」，芯片三条：帮我写一个Java后端校招JD、帮我筛选我发布职位的候选人、列出我发布的职位。输入框占位「输入问题，Enter 发送，Shift+Enter 换行」，0/2000。和学生学习助手是同一组件，角色文案不同。

(a) 14.4 秒返回。气泡标「调用工具 generate_job_description」。正文：

- 职位描述把星澜科技有限公司写进去了（当前企业，不是串到别的公司），但写「使用京东等技术栈」。

## 和学生端的技能词汇是否同一套

对照学生审计（档案页）和本次企业界面：

- 是同一本 `skill_tag`。学生添加技能的下拉是 `名称 (方向)`（半角括号），企业发职位是 `名称（方向）`（全角括号）。两边都能搜到 Java、Docker、Kubernetes、LangChain，方向都有后端开发、前端开发、数据开发、人工智能。
- 学生可以「或自定义新技能」（自由名称 + 方向可创建）。企业职位多选没有 allow-create。自定义技能不会自动变成职位可选 tag，词表会分叉。
- 学生熟练度是 5 星，文案入门/掌握/熟悉/熟练/精通。企业看候选人是「Java · 4」。同一数字，两套界面。
- 学生职位卡片和推荐有匹配分（哪怕分不准）。企业候选人列表没有匹配分，看板技能图也不按「职位要求 vs 候选人」对比。技能系统在企业侧只完成了「打标签」，没有完成「用来筛」。
- 学生就业助手示例是三方协议、推荐岗位、薪资、缺什么技能。企业示例是写 JD、筛候选人、列出职位。组件相同。企业问运营数据时却落到学生那句「问学校就业指导中心」。
- 分类树企业侧多出「测试分类」；技能词表多出「Rust测试」。学生审计里推荐岗位也出现过不属于该生的 STM32/RTOS。测试数据在两边词表和推荐里是通的。
