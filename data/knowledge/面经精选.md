# 面经精选

## Java 后端一面

面试从自我介绍开始，控制在一分半，只讲学校、方向和一段最相关的项目。项目追问集中在 Spring Boot 接口分层、事务在什么情况下失效、MySQL 为什么选择当前索引。准备一个慢查询例子：哪里看执行计划、如何避免回表。Redis 被问到缓存穿透和过期策略时，结合自己是否真的用过再回答，没有用过就说明课程里的理解。算法题常见数组、链表和二叉树，先说复杂度再写代码。手写结束会问测试用例，主动补空集合和重复元素。

## 数据开发一面

数据岗关注 SQL 和一条离线链路。准备一条你能讲清的链路：数据从业务库到明细层、汇总层，用什么调度，失败如何重跑。SQL 题会给两张表，要求分组、窗口函数或去重。说明 Spark 时讲清宽依赖和窄依赖的直觉即可，不必背全部源码。被问到数据倾斜，举一个 key 分布不均的例子和你知道的处理办法，例如加盐或过滤异常 key。如果项目规模很小，直接说数据量，不要把本地作业说成生产集群。

## 前端与测试补充

前端面试常让你讲一个组件的状态从哪来、请求放在哪里、列表为什么重复渲染。准备浏览器输入网址后的过程，但按自己的理解分段，不要整段背诵。测试开发会问如何设计登录用例、如何定位一个偶发失败。把用例分成正常、边界和异常三类，并说明你如何记录缺陷。无论什么方向，面试官问“还有什么要问的”，可以问团队目前的技术栈、新人导师和试用期考核方式，不要第一句就只问加班费。

## 复盘方法

每场面试当天记录三列：问到且答清的、答模糊的、完全不会的。模糊的当晚补一页笔记，完全不会的只选一个主题深入，不要同时新开五个框架。同一道题第二次被问到时，答案应比第一次更短、更有例子。把失败的面试也写成面经，但不要在公共社区泄露公司和题目的未公开试卷。本平台社区里的面经需要审核后才展示，阅读时区分“个人经历”和“公司官方要求”。

## 诚信

不要在面经和简历里使用别人的项目数据。面试官可能要求共享屏幕打开仓库或解释某一行代码。被发现经历不真实，通常会终止流程，学校就业诚信记录也可能受到影响。可以告诉面试官“这是课程项目，数据是模拟的”，模拟数据不影响对思维过程的评价。
## 项目追问清单

建议提前写下十个可能被追问的点：数据从哪来、表结构是什么、为什么选这个框架、接口如何鉴权、失败如何重试、日志看哪里、如何测试、如果流量增加十倍先改哪里、你没做的部分是谁做的、如果重做会改什么。每个点用三句话回答。遇到完全没做过的部分，说“这一块是同学负责的，我了解的接口是……”，然后把自己负责的边界讲清楚。面试官给出提示时顺着提示改，不要坚持错误答案。面试后把新问题补进清单。下一次面试从清单里抽三点复述，直到能不看笔记讲完。课程项目也可以使用这张清单，关键是边界诚实、细节具体。

算法题写完后用一个最小例子走读，能发现大部分边界错误。面试官改变题目条件时，先改思路再改代码，不要在错误思路上打补丁。数据岗的现场 SQL 可以先写清晰版本，再谈优化。后端岗如果被问到没有用过的中间件，说明自己用过的替代方案和两者差异，表现学习能力即可。面经只记录题型和思路，不粘贴公司未公开的完整试卷。

复盘笔记按方向分文件保存，下周面试前只看与该方向相关的三页，避免把所有公司的问题混在一起临时背诵。

如果一轮面试超过四十分钟仍停留在自我介绍，主动把话题收束到项目，礼貌地说“我可以用一个接口设计说明我的工作”。

面试结束离开前确认自己的简历是否需要留下，以及结果大概几天内通知。
