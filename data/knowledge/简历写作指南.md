# 应届生简历写作指南

## 篇幅与基本信息

应届生技术简历建议一页，内容特别多时不超过两页。页眉写清姓名、手机、邮箱、求职意向城市和方向，例如“杭州 / 后端开发”。照片不是技术岗的硬性要求。学号、身份证号、详细家庭住址不必出现。政治面貌、身高体重与岗位无关就不要写。邮箱使用稳定的个人邮箱，避免毕业后学校邮箱失效。文件名采用“姓名-方向-学校.pdf”，不要发送“简历最终版最终.doc”。

## 教育背景与技能

教育背景倒序排列，写明学校、专业、学历、起止年月和核心课程。成绩排名前百分之三十可以写排名，否则用相关课程成绩代替。技能按熟练程度分层，不要把只写过一次作业的技术标成精通。推荐写法是“熟悉 Java 集合、多线程和 JDBC；使用过 Spring Boot、MySQL 和 Redis”。证书写明名称和获得时间，四六级可写分数。技能词应与目标岗位描述中的关键词一致，方便系统和人工同时检索，但不要堆砌岗位里出现、自己却无法解释的名词。

## 项目与实习的 STAR

每个项目用四五行说清背景、任务、行动和结果。背景说明业务场景，任务说明你负责的模块，行动写技术选型和你做过的设计，结果尽量量化，例如“接口平均响应从 800 毫秒降到 200 毫秒”或“覆盖三个核心流程的自动化用例”。课程大作业可以写，但要诚实标明是课程项目。团队项目必须区分“我们”和“我”，面试会追问你画过的图和写过的类。实习经历优先于在校项目，写明公司、岗位、时间和可公开的业务，涉密内容用“内部业务系统”代替真实名称。

## 常见问题

避免大段自我评价空话，例如“吃苦耐劳、领导力强”。兴趣爱好一行即可。空白期超过三个月可以在面试时说明，简历上不必长篇解释。薪资期望可以不写在简历上，放到网申表或沟通环节。中英文简历内容要一致。导出 PDF 前检查分页，不要让项目标题落在页尾。投递不同方向时准备两个版本：后端版突出 Java 和数据库，数据版突出 Python、SQL 和 Spark，不要一份简历同时写十个方向。

## 投递前核对

对照岗位职责逐条看自己是否有对应证据。缺少的技能不要虚构，可以写“正在学习”。联系方式拨打一遍，确保招聘季手机畅通。作品链接如果是 GitHub 或个人站点，仓库应能打开，README 用中文写清如何运行。简历里的每一行都要能展开讲两分钟，写不出来的句子删掉。
## 用词与版式

使用具体动词：设计、实现、排查、优化，少用“参与”“负责相关工作”。数字和单位写完整，不要只写“提升了很多”。中文简历正文用宋体或黑体，字号不小于五号，页边距留出打印空间。技能和项目的时间用“2025.03–2025.06”这种格式，避免“去年夏天”。链接用短地址，二维码会占空间，技术岗可以不放。投递外企或联合培养岗位时再准备英文简历，英文项目与中文项目一一对应，不要出现中文有、英文没有的经历。保存一份纯文本备份，防止招聘系统解析 PDF 时把两栏排版读乱。两栏简历看起来紧凑，但很多网申解析器会把左右栏串行，校招建议用单栏。

投递数据岗位时，把 SQL、数仓或可视化项目放在第一段；投递后端岗位时，把接口、数据库和缓存放在第一段。同一项目可以有两种写法，但事实不能矛盾。课程成绩只列与岗位相关的三到五门。开源贡献如果只有文档订正，就写成文档贡献，不要写成核心开发。简历底部可以放“作品与代码”链接，并注明哪一个仓库对应哪一段项目。

投出前让同学只看三十秒，看不清求职方向就继续删减。
